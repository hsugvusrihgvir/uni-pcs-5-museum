# Система бронирования

```text
1. Посетители
    1.1. Создать посетителя (регистрация)
    1.2. Просмотр всех клиентов
    1.0. Назад
2. Управление бронированиями
    2.1. Создание бронирования - статус CREATED если цена NULL, иначе CONFIRMED
    2.2. Вывод всех бронирований
    2.3. Получение бронирования по ID
    2.4. Изменение бронирования (по ID) — статуса или добавляем цену (переход в CONFIRMED)
    2.5. Удаление бронирования
    2.0. Назад
3. Поиск бронирований
    3.1. Поиск по ID посетителя
    3.2. Поиск по названию выставки
4. Фильтрация бронирований
    4.1. Фильтр по статусу
    4.2. Фильтр по диапазону дат
5. Сортировка бронирований
    5.1. Сортировка по дате (сначала новые)
    5.2. Сортировка по цене (сначала дорогие)
6. Статистика
    - Всего клиентов в системе
    - Всего бронирований в базе данных
    - Всего совершенных бронирований (COMPLETED)
    - Всего отмененных бронирований (CANCELLED)
    - Всего собрано денег (у COMPLETED)
7. Экспорт данных
8. Вывести таблицы базы данных
0. Выход
```

# Требование к enum
По тз нужно хотя бы один, нам подходит такое:
```
public enum BookingStatus {
    CREATED,
    СONFIRMED,
    COMPLETED, 
    CANCELLED
}   
```

# Бизнес-правила
По тз бизнес-правила должны быть реализованы в Java-коде, а не только в интерфейсе пользователя.

## Правило 1 (Существование сущности): 
Нельзя создать бронирование на ID посетителя или ID выставки, которых нет в таблице.
## Правило 2 (Логика дат): 
При создании бронирования (пункт 2.1) дата сеанса не может быть вне рамок даты работы выставки.
## Правило 3 (Финансовая валидация): 
Запрещено переводить бронирование в статус CONFIRMED, если цена билета не указана (NULL) или отрицательна. Подтверждение билета всегда требует указания корректной стоимости.
## Правило 4 (Финальные статусы): 
Статусы COMPLETED и CANCELLED являются конечными. Нельзя отменить уже состоявшийся визит (COMPLETED) или отмененное бронирование (CANCELLED), а также изменить данные самого бронирования.
## Правило 5 (Авто-статус при создании): 
При создании бронирования (пункт 2.1) запрещено вручную указывать статус. Система определяет его сама: если указана цена, бронирование создается в статусе CONFIRMED, если цена не указана (NULL) — в статусе CREATED.
